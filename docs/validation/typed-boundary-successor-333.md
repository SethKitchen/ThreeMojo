# Typed CARLA source successors (#333)

The typed boundary successor binds current source and tests. It keeps the
historical lane oracle records unchanged.

The source chain has two steps for the polynomial and its five reviewed
consumers. The typed API step reconstructs the exact conditioned-only source.
The conditioned cubic step records the new local-coefficient operation graph.
A reconstruction of the old expanded source establishes provenance only.
It does not establish equal computed values or preserve the old cubic theorem
as a theorem about the new evaluator.

All other listed steps add checked typed APIs, named SI compatibility adapters,
and their enumerated call-site migrations. Each step binds complete before and
after bytes, token digests and an ordered fixed inverse. An unknown edit fails.
The checker also binds current native tests, compile-fail fixtures and their
complete import closure. A digest alone does not authorize a source change.

Physical source capture remains in the existing owned operation. It retains
actual current bytes. It checks source paths, import and caller topology,
checker identity and bound inputs again before a result can escape. A caught
failure invalidates the operation. No validation result is cached.

Historical record checks use the named predecessor only after current-source
admission. Their assertions about old function bodies are historical claims.
The current cubic certificate obligations come from the conditioned cubic
successor. Native execution, compiler diagnostics, runtime limits and coverage
remain separate gates.

## Lookup scope of newly bound native consumers

The current native closure imports ten additional namespace families.
These families were absent from the historical CARLA closure. They are
`animation`, `cameras`, `core`,
`exporters`, `geometries`, `lights`, `materials`, `objects`, `postprocessing`,
and `renderers`.

Their bare namespace names are protected at the repository
root, every physically discovered maintained `main` directory, and every
explicitly bound native/compile-fail test directory. `render` keeps the separate
qualified main-branch rule. All pre-333 families retain their previous policy.
Exact consumed module/prefix coordinates, alternate suffixes, package
initializers, case variants and symlinks remain protected everywhere. Supplied
include roots retain the conservative policy with no scoped exception.

The concrete benign case is `assets/geometries/`, an asset directory outside
those lookup roots. It is not individually allowlisted. The maintained Mojo
resolver (`tools/affected.py:resolve`) searches the compiled entry directory
and `-I` repository root for qualified imports. It does not prepend the parent
of each imported library.

Consequently a library's `geometries.shape` import
cannot resolve to `assets/geometries/shape.mojo`. An explicit
`assets.geometries.shape` import can, and would add its physical exact prefixes
to the bound closure. A newly added entry in `assets` changes the complete
source and entry census and is refused.

This rule does not authorize new relative-import syntax. All current
dependency bytes and import inventories remain exact. A new relative import
is refused before reuse of a proof.

The new resolver regression tests cover the asset case and every old-family
refusal. They cover root/test/production-entry competitors, package/compiled
alternates, qualified imports from libraries, and a newly introduced entry root.
Current
owned-operation tests add late source/provider/native-witness changes,
namespace/table mutation, symlinks, new packages/entries and sticky caught
failures.

The maintained compiler witness `probe_typed_namespace_lookup.py` passed all
six cases for all ten families under Mojo 1.1.0 (8189361e). The four positive
programs distinguish root (sum 170), entry-package (230), new asset-entry
(990), and explicitly asset-qualified (990) lookup. Missing root providers
and an entry prefix module both refuse module resolution. Thus a bare import
from a library does not acquire that library's parent directory as a search
root. This independently supports excluding `assets/geometries/` when
`assets` is neither a compiled entry directory nor an explicit include root.
Adding such an entry or a qualified asset import changes the captured entry
or exact import inventory and cannot reuse an existing admission.

`carla-namespace-lookup-333.json` summarizes the completed witness. It binds
the exact probe script, compiler version, six case outcomes and time limits.
The original protocol and build logs are retained separately. This portable
summary does not replace raw evidence or admit a current source graph.

The 300-second outer protocol retained 40-second build and 5-second program limits. It completed
in 18.72 seconds with source, SDK and protocol unchanged and no live children.
This lookup qualification is separate from final current-graph admission.

text view, that view's tokens must first match the independently read current
physical bytes. Only those canonical physical bytes can enter an exact typed
inverse; caller comments never authorize a changed physical file. Stale
historical supplied tokens cannot stand in for current source.

The resulting predecessor is used only for the named historical family check.

## Reconstruction workload

Complete current admission checks every endpoint's full bytes and token
digest. Each later provenance reconstruction independently checks its live
edge digest, complete current bytes, ordered nonoverlapping inverse spans,
and complete predecessor bytes. These byte identities determine the token
identity, so reconstruction need not tokenize them again in the unchanged
canonical parser domain. This removes redundant lexical work without retaining
any verifier result or source projection. Replaced public token helpers still
execute; a changed parser domain fails closed even when an existing lexical
LRU contains a previously computed digest. Complete admission and final owned
re-admission retain their token obligations and physical rereads.

The reduced reconstruction workload is enabled only for the captured canonical
Python 3.12 parser domain. The maintained CI jobs pin Python 3.12.14, including
the digest-pinned coverage image. Other Python versions use the conservative
repeated-tokenization fallback; the 45-second trials do not establish a timing
claim for that fallback. Helper/code identities and immutable snapshots of
positional and keyword defaults are rechecked, including mutable JSON keyword
defaults. Wrapped public token helpers keep their effects and failure behavior.
