# Correctness, performance, and parity audit

This audit fixes loader boundaries, quadratic work and splat scene integration.
It does not establish complete three.js parity or a defect-free repository.

Review date: September 29, 2026.
Base: `df163976daa3d26195a5e8406f496cc81a728031`.
Branch: `codex/audit-correctness-performance`.
Toolchain: Mojo 1.1.0 (`8189361e`), with MAX 26.6.0 for host layout tests.

## Scope

The inventory contains 407 production modules, excluding package initializers.
They contain about 300,000 lines, including comments and tables.
The initial repair pass had 330 executable suites and 209 compile-fail cases.

Detailed tracing focused on Gaussian splat loaders, renderer ordering, ownership,
allocation, fixture provenance, and documented compatibility limits.
The review also checked build rules, selection, fracture geometry, node materials,
and the boundaries of large rendering modules.
This was not a line-by-line review of every production module.
The earlier repairs in `docs/repository-audit.md` are not new findings here.

## Repairs

P1 means invalid input can produce invalid data, an abort, or excessive allocation.
P2 means a narrower API, performance, or validation defect.

| Priority | Finding and evidence | Change |
| --- | --- | --- |
| P1 | The glTF splat accessor accepted a negative offset and read before its buffer view. A regression test failed on the base revision. Buffer indices, strides, lengths, and allocation counts also lacked complete checks. | Validate counts, buffer references, offsets, alignment, stride, and both view bounds before allocation. Use subtraction for range checks. Limit each accessor to ten million elements. |
| P1 | The glTF splat buffer reader ignored declared `byteLength`. A view could read GLB padding or other supplied bytes beyond that length. | Reject short buffers and negative lengths. Trim surplus bytes. Only the first buffer can use the GLB binary chunk without a URI. |
| P1 | The direct SPZ v4 entry point accepted a wrong magic or version. A regression test failed on the base revision. Its 64-bit compressed lengths were assembled into a signed integer. | Check the header and table location. Compare an unsigned stream length with the remaining bytes before conversion or addition. |
| P1 | Raw SPZ versions 1 through 3 lacked the splat count limit used by v4. | Apply the same ten-million-splat limit before decoding. Reject negative harmonic degrees in the public SPZ and KSPLAT helpers. |
| P1 | A compressed KSPLAT section could have no bucket center and use its first row as that center. A regression test failed on the base revision. | Require complete centers and consistent full and partial bucket counts for nonempty compressed sections. |
| P2 | Default and custom renderer sorts used insertion sort for every list size. Reversed depth order required quadratic work. | Add a shared stable merge sort for large lists. Keep insertion sort through 32 entries. Return after a linear scan for ordered lists. Preserve draw indices, keys, orders, sources, and tie order. |
| P2 | SPZ and KSPLAT copied whole output arrays when ownership could move. glTF initialized output elements only to overwrite them. | Transfer owned lists with moves and swaps. Use capacity and append after validating stored glTF attributes. Preserve initialization on raising paths. |
| P2 | X11 tests polled for a minute after a missing executable or failed server process. An empty display line also passed the startup check. | Check for Xvfb before starting it. Stop polling when the child exits. Clean up failed starts and reject an empty display number. Keep failure visible. |

The first three diagnostic regressions all failed on the original code because no
error was raised. The final boundary suite contains eleven tests with multiple
malformed cases per test. The valid three.js splat fixtures still pass.

## Performance evidence

`bench/renderer_sort_bench.mojo` compares the previous insertion implementation
with the new renderer sorter. It checks that all three output arrays match.
The input copy is outside the timer. Each result is the best of three runs.

| Input | Draws | Previous, ms | New, ms | Ratio |
| --- | ---: | ---: | ---: | ---: |
| Sorted | 1,024 | 0.0155 | 0.00827 | 1.87x |
| Reversed | 1,024 | 8.79 | 0.162 | 54.4x |
| Sorted | 8,192 | 0.169 | 0.0895 | 1.89x |
| Reversed | 8,192 | 361.84 | 1.85 | 195.6x |

These are local sorting measurements with concurrent compiler work.
They do not measure frame rate or GPU performance.
The comparison-count test also checks the algorithm without wall-clock timing:
an 8,192-element reversed list stays below `8192 * 13` comparisons.
The new large-list path uses O(n log n) comparisons and O(n) extra storage.
Small and already ordered lists avoid sort-buffer allocation.

## Follow-up repairs

The follow-up adds these changes to the loader and sort repairs above.

| Area | Change | Evidence |
| --- | --- | --- |
| Selection | Build linked object indexes once per selection. Preserve node traversal and each object's input order. | Existing selection fixtures and a sparse 100,000-node index case. Index storage and construction are O(nodes + objects). |
| Fracture | Replace the vertex-count-squared Boolean matrix with a set of directed edge pairs. | Existing indexed, unindexed and coplanar three.js cases. Face-pair traversal remains unchanged. |
| Shared glTF validation | Use `AccessorLayout` for count, alignment, stride, padded matrix layout and view bounds in both loaders. | Main glTF suite, splat suite, malformed boundary cases and direct matrix padding cases. |
| Sparse splats | Overlay sparse values on a stored or zero base. Validate packed views, unsigned indices, order and range. | An integer above Float32's exact range survives without rounding. |
| Scene splats | Register owned splats with a scene. Prepare and order their runs with other transparent objects. | A transparent plane overlaps a splat. Serial and parallel pixels match. Clone geometry is independent. |
| Viewport and glTF placement | Project splats into an optional viewport. Load splat nodes with transforms, names, extras and mesh instances. | Offset projection, nested transforms, duplicate names, multiple primitives and GLB cases. |
| State preservation | Clone splat geometry and preserve nodes that carry splats during scene optimization. Refuse exports that would omit splats. | Clone, optimizer carrier and export rejection checks. |
| Output policy | Count splats as blended light when validating tone-mapped data materials. | A data material with splats raises before drawing. |
| Pipeline boundaries | Extract render-list ordering. Isolate the pinned private task-runtime import in `render/tasks.mojo`. | Existing renderer and sort suites. Public renderer imports remain valid. |
| Fixture provenance | Record 33 generator families, version evidence, commands and artifact hashes. Pin the benchmark to its existing locked three.js version. | `tools/fixture_manifest.py` and drift tests. No fixture was silently regenerated. |
| Node compatibility | Publish the supported serialized classes and test rejection of unsupported classes. | Node loader suite. |

The GPU mixed-draw path packs splats after point vertices in the same device
buffer. It retains the kernel's argument count and shares splat fragment math.
A new device test compares mixed splats and transparent meshes inside a viewport.
Device compilation does not establish pixel parity on hardware.

## Validation

The first repair pass passed 313 focused CPU tests, 40 GPU host tests and all
209 compile-fail cases. Its four-module coverage was 1,107 of 1,107 obligations.
Those figures describe the first pass, before the scene integration in this PR.
They are not full coverage of the final changes.

The follow-up passed 615 CPU tests in 16 suites. All 22 changed production
modules passed with warnings treated as errors. The CUDA suite compiled for
`nvidia:sm_75`. Formatting, documentation and all 18 Python tooling tests passed.
All 40 GPU host tests and all 209 compile-fail cases also passed.
The full `make check` and repository-wide `make coverage` gates are not established.
The host has no physical GPU. Its Xvfb cannot open the required local sockets.
Keep this change in draft until a suitable runner completes the required gates.

Reproduce the focused follow-up checks:

```sh
make test-cpu JOBS=2 CPU_TESTS='tests/test_audit_followup.mojo tests/test_gltf.mojo tests/test_selection_box.mojo tests/test_node_loader.mojo tests/test_gaussian_splat.mojo tests/test_gaussian_splat_loaders.mojo tests/test_scene_optimizer.mojo tests/test_renderer.mojo tests/test_splat_boundaries.mojo tests/test_renderer_sort.mojo tests/test_sort_utils.mojo tests/test_geometry_tools.mojo tests/test_render_hooks.mojo tests/test_multi_material.mojo tests/test_visibility.mojo tests/test_rasterizer.mojo'
make test-gpu-host
make fmt-check docs-check test-tools
python3 tools/fixture_manifest.py
```

Then run `make check`, full `make coverage` and GPU parity on a supported host.
Do not interpret a skipped hardware test as a pass.

## Work still open

This PR does not complete the original request for every audit item or establish
a defect-free repository. These items remain explicit follow-up work.

| Item | What is still required |
| --- | --- |
| Volume parity | Implement scene-depth termination, rectangular area lights and `receivedShadowNode` along the ray. Add upstream image reference cases and CPU/GPU parity tests. |
| TSL and storage buffers | Implement the unsupported serialized classes and direct material storage-buffer reads. Function bodies absent from upstream JSON cannot be recovered by a loader. |
| GPU tile candidates | Measure a tile-based splat candidate list on a physical GPU. Host timing cannot justify a device performance claim. |
| Sort scratch reuse | Profile representative scenes before retaining merge buffers. Check memory retention, reentrancy and ownership. The ordered path already avoids allocation. |
| Broader architecture | Render-list and task boundaries are extracted. Host/device packing and node validation/execution remain in large modules. Further extraction needs stage-specific regression coverage. |
| Serialization | Scene JSON and glTF exporters reject registered splats until serialization is implemented. Splat ray picking still uses its explicit object API. |
| glTF naming | Nodes reserve unique names, but meshes are allocated in file order. Upstream node traversal can allocate them in another order. |
| Fixture provenance | The original sRGB table generator has no recorded three.js version. The VTK XML dependency version is also unrecorded. Preserve these unknowns until a reviewed regeneration supplies exact pins. |
| Validation | Full platform checks, final 100% coverage and physical GPU parity remain release gates. |

`assets/fixture-manifest.json` records the historical release stated by each
generator. Abbreviated releases such as 0.180 map to the exact npm version 0.180.0.
The hashes cover committed family inputs and expected outputs. They prove local
integrity, not that an unrun regeneration will reproduce every byte.
Run `python3 tools/fixture_manifest.py --commands FAMILY` to see the recorded steps.
